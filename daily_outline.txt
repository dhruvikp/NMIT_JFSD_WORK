Factory function:
	A factory function is a normal function that returns a new object.

	It is called factory because it produces objects.

	Basic way of creating object has lot of problems
		- Duplicate Code
		- Hard to maintain
		- Not scalable.


	Factory function:
		function createPerson(firstName, lastName) {
    return {
        firstName: firstName,
        lastName: lastName,
        fullName: function() {
            return `${this.firstName} ${this.lastName}`;
        }
    	};
	}

	- Code reused
	- cleaner
	- scalable.

	Hidden Problem: Memory Inefficiency:

	Every time you call createPerson() function:
		- A new object is created
		- A new copy of getFullName() is created.

	Waste of memory when many objects are created.


	In order to optimize it, 

	Step 1: Remove method from object and have separate object for all methods assignments.

	- Manual assigment
	- Bad for many methods.


	Solution: Using Object.create() (Prototype based factory)
		Object.create(proto)

		}

		- One shared method
		- Prototype based
		- Scalable.

Tool that helps software teams manage changes to the source code over time.
- every modification made to the code 
- developers can go back to earlier versions of the code and compare changes.

Two types of VCS
1. Centralized VCS

	single server where all versioned files are stored.

	Problems:
	- If central server fails, -- all history may be lost
	- collaboration is limited when disconnected from the server

Tool: SVN

2. Decentralized VCS

	Every developer has local copy of entire repository, including history. 
	Changes can be made locally and later pushed to the central repository when ready.
 
 Pros:
 - Every dev has full copy of project's history
 - work can be continued offline
 - more robust against server failures.

 Cons:
 - More disk space
