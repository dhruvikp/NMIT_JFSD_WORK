VCS - Version Control System

Tool that helps software teams manage changes to the source code over time.
- every modification made to the code 
- developers can go back to earlier versions of the code and compare changes.

Two types of VCS
1. Centralized VCS

	single server where all versioned files are stored.

	Problems:
	- If central server fails, -- all history may be lost
	- collaboration is limited when disconnected from the server

Tool: SVN

2. Decentralized VCS

	Every developer has local copy of entire repository, including history. 
	Changes can be made locally and later pushed to the central repository when ready.
 
 Pros:
 - Every dev has full copy of project's history
 - work can be continued offline
 - more robust against server failures.

 Cons:
 - More disk space

 Tool: Git,


 Git

 - Distributed - Every dev has a full copy of the repository
 - Fast and efficient for handling large projects
 - supports branching and merging.

 How git stores data?

 1. Snapshot based storage (git)

 	takes snapshot of entire project directory at time of each commit.

 	commit1 --> snapshot

 	Faster



 2. Delta - based storage (C - VCS)

 	initial change --> delta1 --> delta2 --> delta3

 	space efficient --> very slow down performance

Scrum:

Sprint -  Product is built in series of repetition called sprints.  It breaks down  big complex projects into bite-sized pieces. It makes project more managable, allows team to ship high quality, frequent delivery.

Short, time boxed perioed --> 

Spring - 15 days/ 30 days

Product backlog
	Product backlog is list of all features, bugs, improvements needed for the product, prioritize by importance.



Sprint backlog
	List of task , features, bugs, improvements needs to be completed during sprint


Scrum Roles:
	1. Scrum master
		Scrum master helps team stay focused on their sprint goals and removes any obstacles that are slowing down,
		All meetings or scrum ceremonies has been followed or not.

	2. Product owner
		Product owner decides priority of the items in the backlog

	3. Development team
		Developers + testers work together

Scrum ceremonies 
================
	1. Sprint planning
		team meets at start of the sprint to decide that they will work on implementing which features in next two weeks.

	2. Daily scrum
		Every morning, 15 mins, to discuss what they did yesterday, what they plan to do today and roadblocks

	3. Sprint review 
		just before sprint ends, developer/qa demo it to PO.

	4. Sprint retrospective
		After sprint ends, what went well, what didn't , how they can be improved in next sprint.

	5. Backlog refinement
		Product owner and team review the backlog and make sure that each item is clear and ready for the next sprint.

Working aggrements:
Set of rules that the scrum team agrees to follow smooth collboration.
